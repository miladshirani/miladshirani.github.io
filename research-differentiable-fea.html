Computational Mechanics · Differentiable Programming

Differentiable FEA
without a stiffness matrix.

A finite element solver for large-strain hyperelasticity, written in purely functional PyTorch. Derivatives come from automatic differentiation, equilibrium from a matrix-free Newton-Krylov iteration, and design gradients from one extra linear solve.

Most finite element codes assemble a global tangent stiffness matrix and factorize it. For large nonlinear problems that matrix is the bottleneck, and differentiating through the solver is awkward. This project takes a different route: the stiffness matrix is never assembled. The internal force comes from the weak form, every derivative is obtained by automatic differentiation, and the whole solver is differentiable, so it can sit inside an optimization or learning loop.

Formulation

The solver handles displacement-based, 2D plane-strain finite elasticity with Q4, Q8, Q9, Tri3 and Tri6 elements, and hyperelastic laws including neo-Hookean, Mooney-Rivlin and Saint Venant-Kirchhoff. The unknown nodal displacements \( \boldsymbol{u} \) minimize the total potential energy, which is the same as solving the residual equation

\[ \boldsymbol{R}(\boldsymbol{u},\boldsymbol{p})=\frac{\partial \Pi}{\partial \boldsymbol{u}}=\boldsymbol{f}_{\mathrm{int}}(\boldsymbol{u},\boldsymbol{p})-\boldsymbol{f}_{\mathrm{ext}}=\boldsymbol{0}, \]

where \( \boldsymbol{p} \) collects material and design parameters. The residual is itself obtained by differentiating the strain energy, so adding a new constitutive model means writing only its energy density.

Matrix-free Newton-Krylov

Each Newton step requires the solution of \( \boldsymbol{K}\,\delta\boldsymbol{u}=-\boldsymbol{R} \) with \( \boldsymbol{K}=\partial\boldsymbol{R}/\partial\boldsymbol{u} \). A Krylov method only needs the action of \( \boldsymbol{K} \) on a vector, and that is a single forward-mode derivative of the residual (a Jacobian-vector product):

\[ \boldsymbol{K}\,\boldsymbol{v}=\frac{\mathrm{d}}{\mathrm{d}\epsilon}\,\boldsymbol{R}(\boldsymbol{u}+\epsilon\boldsymbol{v})\Big|_{\epsilon=0}. \]

So the linear systems are solved inexactly, by Krylov iteration with Jacobi or block-Jacobi preconditioning, and \( \boldsymbol{K} \) is never formed. Memory grows linearly with the number of unknowns, and the same code runs on CPU and GPU. Four variants of the operator trade memory for speed, from plain forward-mode AD to tensor-valued moduli stored at the quadrature points. The fastest, an element-wise variant, replaces batched small matrix products by element-wise contractions.

Exact sensitivities

For a design objective \( J(\boldsymbol{u},\boldsymbol{p}) \), differentiating through all Newton iterations would be costly and fragile. Instead the gradient follows from the implicit function theorem, with one extra linear solve at the converged state:

\[ \boldsymbol{K}^{\!\top}\boldsymbol{\lambda}=\Big(\frac{\partial J}{\partial \boldsymbol{u}}\Big)^{\!\top},\qquad \frac{\mathrm{d}J}{\mathrm{d}\boldsymbol{p}}=\frac{\partial J}{\partial \boldsymbol{p}}-\boldsymbol{\lambda}^{\top}\frac{\partial \boldsymbol{R}}{\partial \boldsymbol{p}} . \]

The adjoint solve reuses the same matrix-free operator, and the gradients are checked against finite differences.

Validation

  • Solutions agree with FEniCSx/dolfinx to rounding level (relative difference below \( 10^{-13} \)) on identical discretizations.
  • Cantilever deflections agree with Timoshenko beam theory to about 1%.
  • The stress concentration for a plate with a hole matches Heywood's Kirsch-based formula within 3%.
  • A suite of 194 automated tests passes. Geometries such as notched plates and L-brackets are meshed with Gmsh.

Performance

For a 10,000-element Q4 problem in double precision, a complete nonlinear solve takes 2.9 s on a T4 GPU and 14.7 s on a laptop CPU with 6 threads. The element-wise variant is 11.6 times faster than the first GPU version, because it reaches about 8% of the memory bandwidth instead of 0.7%.

Limits

The code is an early release (v0.1). It covers 2D plane strain on a single process; 3D, multi-GPU execution and multigrid preconditioning are on the roadmap, and volumetric locking appears as the Poisson ratio approaches 0.5.
